# etsuran

家計データを Google Apps Script API から取得する閲覧画面です。
`index.html`・`style.css`・`app.js` で動作します。

## ローカル表示

```sh
python3 -m http.server 8000
```

ブラウザで `http://localhost:8000` を開きます。API 接続先は `app.js` の `API_URL` です。

## 取得と表示

- 読み取り結果はメモリに60秒、最大60件保存します。金額や明細をブラウザストレージへ保存しません。
- 同じ条件の通信は共有し、キャッシュがある画面は即表示します。
- 「更新」でキャッシュを破棄して再取得します。予算の更新成功時も破棄します。
- ホーム取得成功後、カテゴリ→ランキング→月別推移→収支→カレンダー→財産→予算→明細を、通信が空いたときに1件ずつ先読みします。カレンダー・財産・予算・明細はホームで選択中の月・区分を対象とします。
- 推移・ランキング・収支のメニューにフォーカス・ホバー・タッチしたときも対象の読み取りを準備します。
- オフライン、通信量節約設定、2G相当の回線では先読みしません。定期ポーリングや先読みでの書き込みは行いません。通信中・操作直後・非表示タブでは次の先読みを待たせ、選択した画面の取得を優先します。
- 取得失敗は画面内のボタンから再試行できます。明細の本文はスクロール、ヘッダーはスワイプ操作に使えます。

## 動作確認

```sh
node --check app.js
node tests/api.test.cjs
node tests/browser.test.cjs
node tests/prefetch.test.cjs
```

ブラウザテストには Playwright と Chromium が必要です。システムの `/usr/bin/chromium`、または Playwright の Chromium を利用します。別の実行ファイルは `CHROMIUM_PATH` で指定できます。
テストは模擬APIを使用し、実データの取得・予算更新は行いません。スマホ幅で先読み、キャッシュ、連続切替、空データ、エラーと再試行、モーダル操作を確認します。

## GAS API 本体

`gas/Code.gs` は提供されたAPI本体を基にした改善版です。既存の `.gs` のバックアップを取り、同じ関数が重複しないよう本体を置き換えて利用します。画面の `index`・`script`・`style` は別ファイルです。

ホーム集計は月別索引を一度作成し、特別費の年累計は取引ごとに最大12か月へ加算します。従来の加算順序、繰入の除外、月末判定、返却形式を維持しています。予算の合計も各区分の計算結果から作り、同じマスタの再検索を減らしています。集計結果を保持する共有キャッシュは追加していません。

```sh
TZ=Asia/Tokyo node tests/gas.test.cjs
TZ=UTC node tests/gas.test.cjs
```

GASテストは模擬データを使い、既存の単月集計との金額一致、予算マスタの適用期間、空データ、月末・年末・うるう日を確認します。実スプレッドシートへの書き込みはありません。実環境への反映後は、既存のウェブアプリのデプロイを新しいバージョンへ更新して同じURLで動作確認します。

## GitHub Pages

`.github/workflows/pages.yml` は main への反映時に構文・回帰テストを実行し、画面3ファイルだけを公開します。GASコードやテストデータは公開サイトの成果物に含めません。リポジトリの Settings → Pages → Source は GitHub Actions に設定します。

```sh
node tools/build-site.cjs
SITE_ROOT="$PWD/_site" node tests/browser.test.cjs
node tests/prefetch.test.cjs
```

公開用のJS・CSSには内容のハッシュを含むファイル名を付け、更新後に古いキャッシュと混在することを防ぎます。

ランキングAPIは `compact: true` の指定時、全期間の配列だけを返し、期間別の表示は画面で組み立てます。従来形式のAPIにも画面は対応します。GASを更新すると、日付整形の共有・並べ替え回数の削減と応答量削減が有効になります。

## 閲覧制限

画面はアクセスコードでのログインが必要です。GASの `ETSURAN_ACCESS_TOKEN` スクリプトプロパティに16文字以上のコードを設定し、APIの認証対応版を同じデプロイへ反映してください。未設定ではAPIは開放されません。認証情報は公開ソースに含めず、画面では通常はタブのセッションにだけ保存します。「この端末でログインを保持する」を選んだ場合のみブラウザのローカルストレージにも保存し、次回もAPIで認証を確認します。アクセスコードが無効になると保存を解除し、再入力を求めます。

詳細は `gas/導入手順.md` を参照してください。既存の認証なしGASがまだ稼働している間はAPIの閲覧制限は未完了です。右上のkakeiboボタンは初回に専用URLを設定します。URLはそのブラウザのローカルストレージだけに保存し、以後は保存済みURLを開きます。`/connected` と `/connected.html` の両形式を受け付け、接続キーを公開ソースには含めません。
